## 4. Open faults, in the order to fix them

Each one has its evidence. Start from these logs, not from a new probe boot.

**a. The host aborts when the guest names resource 0 (fix first: a guest command must never kill xnuhost).**
- Log `boot-jobs/xnuhost-final.log` (the Mac's copy, the laptop's `boot-jobs/xnuhost-final.log`):
  - `virtio-gpu: command 10c response 1205` twice: `RESOURCE_CREATE_BLOB` refused with `INVALID_PARAMETER`.
  - Then `command 102 response 1203` twice: `RESOURCE_UNREF` of an id the host does not know.
  - Then `external/virglrenderer/src/mesa/util/hash_table.c:311: hash_table_search ... assertion
    "!key_pointer_is_reserved(ht, key)" failed`, and xnuhost ends.
- Mesa's hash table reserves the NULL key, and `virgl_resource_lookup(id)` uses the id as the key, so id 0 asserts.
  Our entry point is `oneios_d2k_resource_exists()` (`runtime/xnuhost/drm2kgsl/glue/oneios_glue.c:134`), called by
  `gpu3d_kgsl.rs` `unref()` and others. That this is the caller is a guess: the log has no stack.
- Fix: refuse resource id 0 at the boundary, both in the glue (each `oneios_d2k_*` that takes a resource id) and in
  `virtio_gpu.rs` (a command naming resource 0 gets `RESP_ERR_INVALID_RESOURCE_ID`). Write a host test that sends
  `RESOURCE_UNREF 0` and the other commands with id 0, and checks that xnuhost lives.
