## 4. Open faults, in the order to fix them

Each one has its evidence. Start from these logs, not from a new probe boot.

**a. The host aborts when the guest names resource 0 (fix first: a guest command must never kill xnuhost).**
- Log `boot-jobs/xnuhost-final.log` (the Mac's copy, the laptop's `boot-jobs/xnuhost-final.log`):
  - `virtio-gpu: command 10c response 1205` twice: `RESOURCE_CREATE_BLOB` refused with `INVALID_PARAMETER`.
  - Then `command 102 response 1203` twice: `RESOURCE_UNREF` of an id the host does not know.
  - Then `external/virglrenderer/src/mesa/util/hash_table.c:311: hash_table_search ... assertion
    "!key_pointer_is_reserved(ht, key)" failed`, and xnuhost ends.
- Mesa's hash table reserves the NULL key, and `virgl_resource_lookup(id)` uses the id as the key, so id 0 asserts.
  Our entry point is `oneios_d2k_resource_exists()` (`runtime/xnuhost/drm2kgsl/glue/oneios_glue.c:134`), called by
  `gpu3d_kgsl.rs` `unref()` and others. That this is the caller is a guess: the log has no stack.
- Fix: refuse resource id 0 at the boundary, both in the glue (each `oneios_d2k_*` that takes a resource id) and in
  `virtio_gpu.rs` (a command naming resource 0 gets `RESP_ERR_INVALID_RESOURCE_ID`). Write a host test that sends
  `RESOURCE_UNREF 0` and the other commands with id 0, and checks that xnuhost lives.

**b. The wallpapers render black, and the host runs out of GPU memory.**
- While the gallery is open, the 13 wallpaper extensions draw at once. `gpu: 10 s: host blobs` climbs to 5,312 blobs
  (2,441 MiB), with about +300 made and +80 freed in each 10 s. Boot 1, with no gallery, reached 3,810 blobs and
  2,486 MiB, so the bytes alone were not higher in boot 2: the refusal may come from the count or another limit (not
  checked). Then blob creates are refused, the wallpapers get no surfaces, and the host swaps (up to 57 MB/s; boot 1:
  under 5 MB/s).
- Find:
  - why so few blobs are freed: a leak of ours, or iOS holds closed surfaces (the `oneios-gpu-ages` and
    `oneios-gpu-kinds` lines)
  - which check returns `INVALID_PARAMETER` for `CREATE_BLOB` (`runtime/xnuhost/src/virtio_gpu.rs`)
  - how to keep host memory under the limit without swap, under the "iOS's RAM is never swapped" rule
- Also: our Metal plug-in cannot compile WeatherPoster's `vfx` render pipelines (`problem render pipeline ...
  vfx_fragment linked 0+13`, `compiler untried`) or iconservicesagent's specialized functions `_asgDownH`/`_asgDownV`
  (`EntryNotFound ... available: 233`). They repeat for the whole session.

**c. The camera shows no picture.** The plug-in makes the device and its streams, CMCapture asks for one stream
(08:17:26 UTC in `boot-jobs/ioslog.txt`), and then gives the streams back at 08:17:28 without starting the graph. So
the host camera is never opened (`camera#0 q0 +2`: the control queue only). CMCapture's errors before that:
- `failed to resolve format 'Photo[FESCompanionFormat]'`
- `Fig assert: "pixelFormatIsSupported"`
- `AVCaptureDeviceFormat '1080p30-16x9-422-10Bit' is derived from FigCaptureStreamFormat ...`
- `Failed to open streams for device Back Telephoto Camera`
- `failed to copy WhiteBalanceGain`

Fix in the capture plug-in (`userland/camera/`, `oneios_camera_formats.c`):
