# The Galaxy A56 (SM-A566E) port

> Port status in this tree (port-a56, 2026-11-21): the version-gated guest-side mechanics are in; the
> OneOS-app-fork side is a proposal in `docs/a56-oneos-fork.md`, not files here. Nothing below changes the
> S24 Ultra / iOS 27 defaults: every A56 behavior is behind an explicit version or boot-arg switch whose
> default is off. Kernel patches 0068/0072–0074/0077 and the loader, staged-GPU, roottweak and `emit.rs`
> changes are **built and host-tested here, but no kernel build or phone boot was run in this pass** — that
> proof is still open (see "Not yet proven").
> Since 2026-11-21 xnuhost recognises the A56 at its start (`galaxy-a56` in `runtime/bridges/hw/host_device.rs`,
> `docs/hardware.md` 7h: `SM-A566*`, `a56x`, `ro.soc.model` `s5e8855`) and defaults to `--gpu 2d` there (no KGSL); the
> fork proposal's other session arguments stay the fork's.

`Musicalista/OneiOS-A56` (17 unique commits vs `main` at 2026-11-13) reached the iOS 16.5 (20F66) lock screen on
a Galaxy A56 5G by running the 16.5 userland on the hosted kernel prelinked with the iOS 27 (24A446) kexts,
plus hosted patches and A56 session arguments. The device result is the fork's; what is in this tree is the
mechanics, adapted so 27.x on the S24 Ultra is untouched.

## The dual-version flow (how version selection works here)

The image set's build names the userland (`manifest.json` `build`, read by xnuhost into `image_set.build`):

- `24A446`: everything as before. The tree, the staged GPU code, roottweak's `xnuhost.conf` and the kernel's
  default paths are byte/behavior-identical to a tree without this port.
- `20F66`: xnuhost publishes the ramdisk as `RAMDisk1` too (loader `ramdisk1`, `runtime/loader`, docs/booter.md
  2.1); roottweak writes that image's `xnuhost.conf` with the 16.5 boot arguments (`oneios-gpu-metal=0`,
  `oneios-legacy-bootstrap-replies=1`, `oneios-legacy-registered-ports=1`, the keybagd + QuartzCore text fixups);
  the kernel's 16.5 shims engage (0068 and 0069/0072/0073 by boot argument, 0074 by layout). 0068 was "always
  compatibly" as ported, and was not: it broke every iOS 27 boot at launchd until 2026-11-21 (the next table). The OneOS fork's session script
  passes the rest (`--display shm --gpu 2d`, frame, `--set` flags): proposal, `docs/a56-oneos-fork.md`.

## Why 16.5 needed each piece (the fork's triage, condensed)

20F66's stock Metal opens `AGXAccelerator` as an IOGPU device client (type 1), which NativeAdreno refuses
(`0xe00002c7`): with the accelerator published, backboardd has a Metal device that cannot draw. `=0` leaves
CoreAnimation on the CPU — yet the panel stayed black, because 24A446's dispatch tables refused 20F66's swap
record (`0xe00002c2`: 0x46c vs 0x6e0) and surface info/limits sizes (0072 rewrites them field by field; the
header/plane maps are in the patch's comment). Then SpringBoard waited forever on
`com.apple.coremedia.systemcontroller.xpc`: mediaserverd died at exec with `OS_REASON_EXEC` 8 — Sandbox
refusing `mac_cred_label_update_execve` (0073 logs the policy, skips it for named executables). Touch is
still open in the fork: touches queue, vsync runs, but only 17 frames in the session and the first 2.25 s
after a touch-down; suspect IOHIDEventServiceUserClient 2/3 (`0xe00002c7`) or the shared-queue event format.

## Licence call (owner)

`ONEIOS_CRYPTO=original` removes the source-corecrypto reason a built kernel may not be released. **The owner's
call (2026-11-21): the hosted `ONEIOS_CRYPTO=original` kernel is the one a release carries** (kernel/README.md
"Releases and licences", docs/releases.md "The kernel in a release"). Its build record counts the source
corecrypto archive's symbols in the kernel (0 of 1191) and says `"releasable": true`; the default build stays
`source` (a local kernel, never released). A prelinked `kernel.kc` is never releasable (Apple's kexts).

## The Xclipse host half (not in this tree; audit of 2026-11-21)

The staged GPU3D amdgpu branch above is the guest side of a 3D path whose host side `main` does not have:
xnuhost here opens only KGSL (`gpu3d_kgsl.c` then, `runtime/xnuhost/src/gpu3d_kgsl.rs` since the Rust port), so on the A56 `gpu=auto` logs `gpu: 2D only: ...` and the guest gets
the 2D scanout (the fork's own 20F66 sessions pass `--gpu 2d` too). The fork's host half exists only as the binary
`tools/xnuhost_a56` (aarch64, NDK r27c, with debug info): its DWARF names `runtime/xnuhost/src/gpu3d_xclipse.c` (a
`--selftest-xclipse`: udmabuf import into the Xclipse GPU VA, a command buffer, a fence), a `gpu3d_kgsl.c` whose
open falls back to `amdgpu_renderer_probe` and whose context create calls `amdgpu_renderer_create` (virglrenderer's
`src/drm/amdgpu`, from a `virgl-android` tree), and libdrm 2.4.133's amdgpu library; it reads
`ONEIOS_AMDGPU_RENDER_NODE`. None of that source is in the fork's git (17 commits read), so nothing could be ported:
the ask to the fork is to publish `gpu3d_xclipse.c`, its `gpu3d_kgsl.c` changes and the libdrm/virglrenderer build.
Binaries never enter this tree. The read-only preflight `scripts/port/verify-host.sh` accepts the A56
(`SM-A566`/`a56x`/`s5e8855`) and prints its render node; `--set panel-fallback=1080x2340@120` gives xnuhost the A56's
panel where none is read (the fork pins `--width 1080 --height 2340` for 20F66 anyway).

## Touch on the A56 (open; audit of 2026-11-21)

Nothing in the fork's tree fixes it: the last fork commit (c6f0938) still says touches are queued to backboardd and
do not become gestures, with IOHIDEventServiceUserClient selectors 2 and 3 answering `0xe00002c7` as the first
suspect. That is an iOS 16.5 userland on 24A446's IOHIDFamily, not the A56's hardware: this tree's input path finds
`sec_touchscreen` by name and event4 is the A56's touch screen (the S24's side-key numbering does not apply). The fix
needs 20F66's and 24A446's IOHIDEventServiceUserClient dispatch tables side by side (Apple files: not here), then a
size-triggered rewrite in the pattern of `0072`. Not attempted without them.
